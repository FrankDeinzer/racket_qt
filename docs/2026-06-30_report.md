### Crash 4 — Stub-Klassen: `parent #f`-Fehler

**Fehlermeldung:** `send: target is not an object, method: get-parent`

**Ursache:** `make-stub-class` rief `(super-new [parent #f])` — ignorierte den echten Parent aus `args`.

**Fix:**
```racket
(define the-parent (if (pair? args) (car args) #f))
(super-new [handle #f] [parent the-parent])
```

Zusätzlich aus `make-stub-class` entfernt: `(error name "not implemented ...")` am Ende.

Fehlende Methoden ergänzt:
- `(define/public (on-combo-select i) (void))` — benötigt von `wxtextfield.rkt` via `override*`
- `(define/public (set-callback cb) (void))` — benötigt von `mrpanel.rkt` für `tab-panel%`

**Betroffen:** `check-box%`, `choice%`, `list-box%`, `slider%`, `radio-box%`, `tab-panel%`

### Crash 5 — `text-field%`: `min-height = -9`

**Fehlermeldung:**
```
min-height in area<%>: contract violation
  expected: (integer-in 0 1000000)
  given: -9
```

**Aufrufkette:** `wxtextfield.rkt:300` → `set-line-count` → `update-size` (wxcanvas.rkt) → `set-min-height(-9)`

**Root-Cause-Analyse:**

`update-size` in `make-editor-canvas%` berechnet:
```racket
new-min-height = fixed-height-lines * line-height + (h - ch)
```
dabei ist `h = (get-size).h` und `ch = admin.get-view().h`.

`h` kommt aus `make-item%`'s gespeichertem `h`-Feld (initial 0). `ch` ist der Editor-Viewport (ein positiver Wert, ~9 px bei der Standard-Schriftgröße). Ergebnis: `0 - 9 = -9`.

**Warum der Seed-Fix zunächst nicht half:**

`base-canvas%` hatte `get-width`/`get-height` überschrieben, um Qt's tatsächliche Dimensionen zurückzugeben:
```racket
(define/override (get-height) (shim_canvas_get_height qt-handle))
```

Auf Windows initialisiert Qt einen neu erzeugten `QWidget(parent)` mit `size() = QSize(100, 30)` — das ist der `CreateWindowEx`-Default für Child-HWNDs. Deshalb sah `make-item%`'s `set-size`-Cache via `same-dimension?`:

```
same-dimension?(100, get-width()=100) → TRUE
same-dimension?(30, get-height()=30)  → TRUE
```

→ `super set-size` wird nicht aufgerufen → `window%`'s gespeichertes `h` bleibt 0.

**Fix:** `get-width`/`get-height`-Overrides aus `base-canvas%` entfernen. `window%`'s Default-Implementierung gibt die *gespeicherten* Werte `w`/`h` zurück (initial 0). Jetzt sieht `same-dimension?`:

```
same-dimension?(100, get-width()=0)  → FALSE
```

→ `super set-size` wird aufgerufen → `window%`'s `h` wird auf 30 gesetzt → `update-size` liest `h=30` → `new-min-height` ist positiv.

Der Seed-Call im Konstruktor bleibt erhalten:
```racket
(when (and (integer? w) (> w 0) (integer? h) (> h 0))
  (send this set-size (if (and (integer? x) (>= x 0)) x 0)
                      (if (and (integer? y) (>= y 0)) y 0)
                      w h))
```

**Betroffene Klasse:** `wx/qt/canvas.rkt`, `base-canvas%`

## 5. Technische Erkenntnisse

### 5.1 Qt-Windows-Default-Größe bricht Layout-Caching

`QWidget(parent)->size()` gibt auf Windows sofort `QSize(100, 30)` zurück — der Win32-`CreateWindowEx`-Default für Child-HWNDs. Das ist plattformspezifisch: macOS und Linux geben `QSize(0, 0)` zurück. Deshalb darf `base-canvas%` `get-width`/`get-height` **nicht** auf Qt's Werte mappen, solange `make-item%`'s `same-dimension?`-Cache aktiv ist. Stattdessen müssen `window%`'s eigene Felder (`w`, `h`) die Wahrheit über die Layoutgröße halten.

### 5.2 `same-dimension?` prüft Deltawert, nicht Absolutwert

```racket
(define same-dimension?
  (lambda (new-dim current-dim)
    (or (= new-dim current-dim)
        (= new-dim -1))))
```

`-1` gilt immer als „unverändert" (Sentinel). `make-item%`'s `set-size` ruft `super` nur auf, wenn mindestens eine Dimension sich geändert hat. Bei gleichem Wert (auch 100 == 100 nach Qt-Default) wird der gesamte Propagationspfad übersprungen.

### 5.3 Konstruktions-Reihenfolge in Racket-Mixins

In einem Mixin-Stack wie `make-item%(canvas-mixin(base-canvas%))` läuft:
1. Innere Klassen-Bodys (base-canvas%, canvas-mixin, …) von innen nach außen
2. `make-item%`'s `super-make-object` triggert die innere Kette
3. Erst *nach* Rückkehr aus `super-make-object` laufen `set-min-width`/`set-min-height` in `make-item%`'s Body

Der Seed-Call in `base-canvas%`'s Body läuft also vor `make-item%`'s Minimum-Initialisierung — genau das Richtige.

### 5.4 `area-parent` und `dx`/`dy`

`area-parent` in `make-item%` gibt `first-arg` (den Parent-Container) zurück. `dx`/`dy` von `wx-make-window%` sind immer 0 (für non-Panel-Widgets). Das x/y-Adjustment in `make-item%`'s `set-size` ist damit für normale Canvases ein No-Op.
