Übergibt die Advisor-Rolle an einen **frischen Chat**, um Token-Last zu senken (ein langer Chat

## Projekt in einem Absatz
Additives viertes GUI-Backend **"qt"** (Qt 6 Widgets, aktiviert via `PLT_QT=1`) für `racket/gui`.
Bestehende Backends (cocoa/gtk/win32) bleiben **unangetastet**. Nordstern: **DrRacket auf Qt**, um
später Browser (Qt-WASM) + Mobile zu ermöglichen. Drei Entwicklungsmaschinen, alle auf **Racket
v9.2 [cs]**: Windows (primär; gui-lib als Installation-Link → `raco setup`), macOS arm64 + Linux x64
(beide `-S`-Source-Override → `raco make`). Repo-Root: `C:/src/racket_qt/`.

## Tragende Invarianten (Details in CLAUDE.md — hier die kritischen)
- **KEIN `QApplication::exec()`, KEIN `QEventLoop`, keine geschachtelte Schleife.** Racket treibt,
  Qt wird gepumpt via `shim_pump(0)` — der Pump blockiert NIE. Das ist die zentrale Wette; sie ist an
  ihrem härtesten Fall (nativer Datei-Dialog) bestätigt.
- **C→Racket-Callbacks**: `#:atomic? #t`, nur Events posten, nie synchron. Callbacks müssen
  Racket-seitig **RETAINED** werden (sonst GC → `invalid memory reference`). Einmal-Trampolin-Muster
  (ein `function-ptr` beim Modulladen, Dispatch über ID) statt frischer Closure pro Aufruf.
- **public*/override*-Invariante** (HACKING §1): Diskriminator = Kontrakt gegen gtk/win32/cocoa,
  nicht raten.
- **Zwei-Repo-Commits**: gui-Submodul zuerst, dann Umbrella-Zeiger. Nur ff-Pushes/-Pulls.
- `queue-backing-flush` → `(void)` (HACKING §4). `frame%.direct-show` ruft `register-frame-shown`
  (HACKING §3).
- Zeichnen: Cairo→Backing-QImage→`shim_canvas_blit_argb`→`paintEvent`; `ARGB32_Premultiplied`,
  stride aus `cairo_image_surface_get_stride()`. HiDPI=1.

## Bewährtes Arbeitsmuster (das, was funktioniert hat)
- **MESSUNG-VOR-FIX** mit instrumentierten Diskriminatoren (gated hinter `PLT_QT_DEBUG`). Wiederholte
  Lehre: die Bugs waren fast immer **mundan im gemeinsamen Racket/Shim-Pfad**, NICHT das
  Event-Loop-Modell. A-priori-Modell-Hypothesen hatten schlechte Trefferquote.
- **Nativ-Backends (win32/gtk/cocoa) als Kontrakt-/Vollständigkeits-Referenz lesen und spiegeln.**
- **Orakel-Disziplin**: nicht spekulativ Widgets bauen, sondern DrRacket (oder ein gezieltes
  Probe-Skript in `examples/`) sagen lassen, welche Widgets ein Dialog wirklich zieht. (Lektion: der
  vermutete Recovery-Dialog-Treiber zog die Zielwidgets gar nicht — vor dem Bauen per Code-Lektüre
  prüfen.)
- **OS-Split**: Windows führt (Fix), macOS/Linux validieren nach Push. Explorative Schritte ganz auf
  Windows (geringste Tooling-Reibung; macOS/Linux bauen sich Klick-/Screenshot-Helfer selbst —
  CGEvent bzw. XTest + eigener XWD-Parser).
- **Light Mode** für visuelle Tests explizit setzen — maßgeblicher Key ist
  `framework:white-on-black-mode?` (=`#f`), NICHT der Legacy-Key `framework:color-scheme` (Falle,
  HACKING §16; eine Dark-Mode-Fehldeutung hat hier schon einen "Bug" vorgetäuscht).
- **Report-Header = gemessene `racket --version`**, nicht kopiert.
- **AskUserQuestion** vor Pushes/Pulls (Regel 7) und vor Scope-Erweiterung/Fixen.
- Nutzer-Präferenz: **"angemessen große Blöcke"**, getrennte Commits als Rollback-Punkte, fehlende
  Infos explizit anfordern, knappe Rückfragen wo möglich.
- Prompt-Form, die trägt: OS-aufgeteilt, Phase 0 misst Umgebung, harte Guardrails, self-gate-
  Checkpoints, explizite OUT-OF-SCOPE-Liste, Zwei-Repo-Commit-Disziplin, "stale-Shim-Falle" (nach
  `shim.cpp`-Änderung macOS/Linux neu bauen).

## Geparkte Befunde (nicht blockierend)
- **Crash B**: `invalid memory reference` nach bereits korrektem `put-file`-Rückgabewert in einem
  Skript OHNE `frame%` (Teardown-Reihenfolge). Eng — nur der Skript-Ende-Pfad. 1/1 reproduziert,
  nicht gefixt (Guardrail: gemeinsamer Code, Entscheidung beim Nutzer).
- **htdp-lib `test-engine:test-dock-size`-Contract-Bug**: extern (htdp-lib, nicht gui-lib),
  plattformunabhängig. Triggert inzwischen schon bei **einem** offenen Tab (Linux; macOS brauchte
  zwei). Isolierter Qt-Repro reproduziert den harten Absturz NICHT. Für die htdp-Schluss-Session
  (Schritt 3). Nutzer-Vermutung: htdp zieht eine breite GUI-Widget-Kette (image/world/test-panels)
  → trifft vermutlich ein noch-nicht-vollständiges Widget.
- **Kleinere**: macOS "Windows"-Menü fehlt (8 statt 9, ungeklärter Datenbefund); Linux
  Resize/Minimieren unter KWin/X11 (ungeklärt); Windows Toolbar-Save-Icon-Timing
  (`wx/qt/button.rkt`); DrRacket Save-As hängt `.rkt`-Endung nicht an (Randnotiz, `setDefaultSuffix`
