## Phase 0 — Hygiene (hartes Gate, vor allem anderen)

**Wichtig zur Verortung:** Die gemessene Verschmutzung (Stand 2026-09-22) liegt auf der
**Windows**-Maschine, nicht hier — dort zeigen Umbrella 89 Dateien, `third_party/gui`
**797** und `third_party/draw` 115 als „modified", alles reine LF→CRLF-Umschreibungen
ohne jeden Inhalt (`git diff --stat --ignore-cr-at-eol` war in allen drei Repos leer).
Betroffen waren auch `LICENSE` und `.github/workflows/` im Fork, die nie eine Session
angefasst hat. **Die Windows-Bereinigung ist ein eigener Kurzschritt und nicht Teil
dieser Session** (s. „Windows-Kurzschritt" unten).

**Was diese Session tut: das eigene Linux-Arbeitsverzeichnis prüfen.** Ob Linux
ebenfalls betroffen ist, ist ungeprüft — vermutlich nicht, weil CRLF-Schreiben ein
Windows-Werkzeugartefakt ist. In allen drei Repos (Umbrella, `third_party/gui`,
`third_party/draw`):

```
git status -sb                         # synchron zu origin?
git diff --stat                        # überhaupt etwas modifiziert?
git diff --stat --ignore-cr-at-eol     # wenn ja: bleibt hier etwas übrig?
```

- **Alles clean:** nichts zu tun, weiter zu 0b. Im Report einen Satz dazu.
- **Modifiziert, aber `--ignore-cr-at-eol` leer:** dieselbe CRLF-Klasse → `git checkout
  -- .` in den betroffenen Repos. Gefahrlos, weil nichts Inhaltliches verloren geht.
- **Irgendwo bleibt ein inhaltlicher Diff: STOPP + `AskUserQuestion`.** Dann liegt
  ungesicherte Arbeit herum, und die darf nicht verworfen werden.

**Prävention (gilt unabhängig davon, ob Linux betroffen ist):** `.gitattributes` im
**Umbrella** mit `* text=auto eol=lf` anlegen und committen — eigenes Repo,
unbedenklich, und es schützt alle drei Maschinen. Für die **Submodule nicht**
committen: das ist der `racket/gui`-Fork, eine `.gitattributes` dort vergrößert die
Divergenz zu upstream grundlos.

### Windows-Kurzschritt (nicht diese Session)

Auf der Windows-Maschine, vor deren nächster Session — sonst landet beim nächsten Commit
ein ~1000-Dateien-Rauschdiff im Fork und `git blame` ist auf 797 Dateien tot:

```
git diff --stat --ignore-cr-at-eol          # in allen drei Repos: muss LEER sein
git checkout -- .                           # Umbrella
git -C third_party/gui  checkout -- .
git -C third_party/draw checkout -- .
git config core.autocrlf false && git config core.eol lf   # auch in beiden Submodulen
```

Ursache dort noch offen: `core.autocrlf` ist unset, Git war es also nicht — die Dateien
wurden physisch umgeschrieben. Verdächtig sind PowerShell-Bulk-Schreibvorgänge
(`Set-Content`/`Out-File` schreiben unter Windows PowerShell CRLF), ein
Editor-„Zeilenenden normalisieren" über den Ordner, oder ein Git-Client mit eigener
Konfiguration. Kurz eingrenzen, nicht ausforschen.

**Self-Gate 0a:** eigenes Arbeitsverzeichnis clean und synchron, `.gitattributes` im
Umbrella gesetzt → weiter.

**Phase 0b — Umgebung + Basislinie (kurz).** `~/racket/bin/racket --version` messen (nicht

## Phase 2 — Fixen, nach Wirkung geordnet

Vorab-Einschätzung zur Priorität und die jeweilige Qt-Entsprechung — **als Startpunkt für
die Messung, nicht als fertige Lösung**:

**2.1 Control-Font-Metrik — zuerst, höchste Wirkung.** `get-control-font-face`/`-size`
speisen die Layout-Metrik **jedes** Controls. `"Arial"` existiert auf den wenigsten
Linux-Systemen, und auf macOS ist es nicht die System-UI-Schrift. Qt-Entsprechung:
`QApplication::font()` bzw. `QFontInfo` für die tatsächlich aufgelöste Familie und
Punkt-/Pixelgröße. Neuer Shim-Export. **Nach dem Fix messen, ob sich Control-Größen
ändern** — wenn ja, ist das ein Layout-Effekt, der die Suite-A-Proben berühren kann und
in Phase 3 sauber eingeordnet werden muss (Verbesserung, nicht Regression).

**2.2 Die billigen, eindeutigen.** `get-double-click-time` →
`QApplication::doubleClickInterval()`; `bell` → `QApplication::beep()`;
`is-color-display?`/`get-display-depth` → `QScreen::depth()`;
`find-graphical-system-path` → gtks Fälle spiegeln.

**2.3 `flush-display` — Vorsicht, Regel 1.** gtk erzwingt hier das Abarbeiten
ausstehender Zeichen-Updates. Die naheliegende Qt-Übersetzung wäre
`QApplication::processEvents()` — **das ist eine geschachtelte Schleife und verboten.**
Richtig ist vermutlich ein `shim_pump(0)`-Aufruf bzw. ein gezieltes Flush ohne
Event-Verarbeitung. Wenn die Messung zeigt, dass der Konsument echte Nesting-Semantik
erwartet: **STOPP, Regel 3** (Subagent + Rückfrage), nicht improvisieren.

**2.4 `has-x-selection?` + X11-Primärselektion.** Nur Linux relevant (Mittelklick-Paste).
Die Clipboard-Infrastruktur aus §36 steht bereits; Qt: `QClipboard::supportsSelection()`
und `QClipboard::Selection`-Modus.

**2.5 `enable-top`.** Die Menü-Maschinerie ist seit §37 verdrahtet; `QMenuBar`s Actions
haben `setEnabled`. Sollte klein sein.

**2.6 Bild-Zwischenablage** (`get-bitmap-data`/`set-bitmap-data`). Qt:
`QClipboard::setImage`/`image`. Die Cairo↔`QImage`-Konvertierung existiert bereits im
Canvas-Blit-Pfad — dort abschauen, nicht neu erfinden (`ARGB32_Premultiplied`, `stride`
aus `cairo_image_surface_get_stride()`, s. Shim-Konventionen).

**2.7 `location->window`, `hide-cursor`, `collecting-blit`.** Erst Konsumenten messen.
`collecting-blit` ist ein Kandidat für **Regel 4**: wenn nichts in DrRacket es benutzt,
Negativbefund dokumentieren und parken statt spekulativ bauen.

**2.8 Aufräumen (klein, aber überfällig):** `make-stub-class` in `platform.rkt` wird
definiert, aber **nirgends aufgerufen** — tote Funktion, entfernen. Und der Dateikopf
behauptet noch „frame%, canvas%, button%, check-box%, list-box% sind echt; der Rest sind
Stubs"; das ist inzwischen aktiv falsch und gehört korrigiert. Vor dem Entfernen per grep
über den ganzen Fork bestätigen, dass es wirklich keinen Aufrufer gibt.

**Triage-Regel (unverändert):** Root-Cause gemessen + Fix in `wx/qt/`/`qt-shim/` → sofort
fixen, eigener Commit, nicht fragen. Fix berührt Shared Code (`wx/common`, `framework`,
`mred/private`) → Subagent + `AskUserQuestion` mit fertiger Empfehlung. Budget (zwei
Hypothesen-Zyklen) erschöpft ohne Root-Cause → Negativbefund dokumentieren, parken, **nie
spekulativ fixen**.

**Shim-ABI:** mehrere dieser Fixes brauchen neue Exporte. Wenn ja, den
Build-Banner-Mechanismus in `CLAUDE.md` bedienen (Konvention aus §27/§52.1), damit
Windows/macOS beim nächsten Pull neu bauen.

## Kontext-Disziplin

Ersten Eintrag im Hauptagenten end-to-end (Methode etablieren), danach je Eintrag an
Subagenten delegieren — **Modellwahl nach `CLAUDE.md`s Abschnitt „Subagent-Modellwahl"**
(Haiku nur für stumpfe Build-/Test-Ausführung, Sonnet+ für alles mit Urteil). Festes,
knappes Rückgabeformat: Eintrag · Konsument + erwarteter Vertrag · Qt-Entsprechung ·
Fix in einem Satz · Verifikation. **Keine Logs, keine Screenshots im Return.** Report je
abgeschlossenem Eintrag fortschreiben, nicht am Sessionende.

angefasst hat. Am 2026-09-19 hat eine gecachte Fenstergeometrie einen Klick in den
