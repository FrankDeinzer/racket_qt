ROLLE & ZIEL
Konsolidierungs-Block — KEINE neue Architektur, kein neues Feature. Drei zusammengehörige Dinge, die
alle am selben Drei-Maschinen-Sync hängen:
  (1) Die zwei macOS-Fixe (id-to-menu-item, retained-callbacks) auf origin bringen und alle drei
      Maschinen darauf synchronisieren.
  (2) VERIFIZIEREN, ob Linux' dokumentierte Crashes A/B (§19 / report-linux) durch diese Fixe
      verschwinden — echter Messschritt, KEINE gesetzte Annahme.
  (3) Zwei kleine Lücken schließen: Windows holt die DrRacket-File→Open/Save-Verifikation nach; die
      Qt-eigen×nativ-Matrix wird auf Linux/macOS vervollständigt (nativer Dialog als flaggbarer
      Datenpunkt).
Reihenfolge: Windows (Push + eigene Lücke) → Linux (Crash-Rückprüfung + Matrix) → macOS (Matrix).

WICHTIGE EINORDNUNG (Erwartung ehrlich halten)
- (3)-Matrix ist reine Abdeckung, voraussichtlich schnell. ABER der native Dialog ist je Plattform ein
  anderes OS-Objekt: macOS = NSOpenPanel/NSSavePanel (kann historisch eine eigene Runloop mitbringen),
  Linux/KDE = evtl. xdg-desktop-portal-Dialog (out-of-process via DBus). Beide werden voraussichtlich
  tragen (non-modaler open()-Pfad ist robust), aber falls einer sich entzieht → FLAGGEN als Datenpunkt,
  NICHT mit exec() erzwingen. Qt-eigener Dialog bleibt Standard, nativ ist Stil-Option.
- (2) ist der eigentliche Wert und NICHT sicher: Linux Crash A war `pre: arity mismatch`, der
  macOS-Crash war `invalid memory reference` — ähnliches Revier (Menü-Dispatch), aber unterschiedliches
  Fehlerbild. „Durch die Fixe mitbehoben" ist plausibel, aber unbewiesen. Messschritt mit Stopp.

HARTE GUARDRAILS
- Kein exec()/QEventLoop/geschachtelte Schleife. cocoa/gtk/win32 NICHT anfassen (nur Referenz).
- KEINE neuen Fixe in gemeinsamem Code auf eigene Faust. Wenn Crash A/B bleibt oder ein neuer Crash
  auftaucht: MESSEN, dokumentieren, STOPP — die Ursache (mutmaßlich wx/common/queue.rkt) kommt zu mir
  zurück, wird nicht in dieser Sitzung gegraben. Einzige erlaubte Code-Änderung: KEINE (dies ist Sync +
  Verifikation + Matrix, kein Fix-Auftrag). Ausnahme nur nach expliziter Rückfrage per AskUserQuestion.
- Zwei-Repo-Commit-Disziplin. Nur ff-Pulls/-Pushes. Gated Diagnose bleibt gated. Report-Header =
  gemessene racket --version. Vor jedem Push/Pull per AskUserQuestion bestätigen (Regel 7).
